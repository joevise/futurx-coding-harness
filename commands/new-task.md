# /new-task 命令规范

## 触发词
`/new-task`、`开一个新任务`、`创建 task`

## AI agent 该做什么

当用户触发 `/new-task` 时：
1. 告诉用户：「好，我们来开一个新 task。先跑 `bash scripts/new-task.sh`」
2. 执行 `bash scripts/new-task.sh`，进入交互式引导
3. 交互式引导分几步：
   - 让用户描述任务（一句话）
   - 工具自动扫描所有进行中的 task，找相似项
   - 强制用户三选一：
     - **[1] 加入已有 task** → 进入双重对齐流程
     - **[N] 独立新 task** → 分配新 ID，继续
     - **[Q] 取消** → 什么都不做
4. 如果用户选择 [1] 加入，必须走双重对齐 3 步：
   - Step 1：告诉用户「请先读完 T-XXX 的 spec/plan/log/decisions」
   - Step 2：联系 owner 达成分工共识
   - Step 3：用户声明自己的具体范围（≥10 字）
5. 工具自动创建目录 + 6 个模板文件

## 示例对话

```
用户：/new-task
AI：好，我们来开一个新 task。
    > 执行：bash scripts/new-task.sh

工具：请描述你要做的任务（一句话）：
用户：加一个货币基金实时申购赎回模块
工具：正在扫描相似 task...
工具：找到 1 个相似 task：T-012 现金管理模块（进行中）
工具：这是你要做的吗？
  [1] 加入 T-012（成为 T-012.1）
  [N] 独立新 task
  [Q] 取消
用户：1
工具：请完成双重对齐：
  ✅ Step 1：读完 T-012 的 spec.md 和 plan.md
  ⬜ Step 2：联系 owner @王哥 达成分工共识
  ⬜ Step 3：声明你的具体范围
用户：我负责申购赎回的 T+0 实现
工具：✅ 对齐完成。创建子任务 T-012.1...
工具：✅ 已创建 progress/tasks/T-012.1-申购赎回-t0/
```

## 失败处理

| 情况 | 处理方式 |
|---|---|
| 用户跳过双重对齐 | 报错「双重对齐是强制流程，不可跳过」 |
| 用户手动建目录 | PR 会被 CI 拒绝，且代码 review 会打回 |
| owner 联系不上 | 先做 Step 1 和 Step 3，Step 2 之后补 |
| 用户选 Q 取消 | 结束对话，不创建任何文件 |
