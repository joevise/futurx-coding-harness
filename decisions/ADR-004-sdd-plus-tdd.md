# ADR-004: SDD + TDD 是叠加关系，不是替代

**状态**: accepted
**日期**: 2026-05-11
**作者**: joey

## 背景
团队对引入 SDD 后是否还要 TDD 存在疑问。

## 决策
**SDD + TDD 同时使用**，分工如下：

```
SDD（规格驱动）解决：做的事正确不正确
  └─ Spec.md → Plan.md
       ↓
TDD（测试驱动）解决：代码实现正确不正确
  └─ 写测试 → 写代码 → 重构
```

### 衔接方式
- Spec 的 **每条验收标准** → 一一对应到 TDD 的 **测试用例**
- Plan.md 中的"测试策略"章节列出 spec → test 的映射表

## 理由

| SDD 不能替代 TDD 的原因 | TDD 不能替代 SDD 的原因 |
|---|---|
| Spec 只描述行为，没有验证手段 | 测试用例不能告诉你"做什么" |
| 没有测试，spec 改了代码不知道 | AI 写出"测试通过但偏题"的代码 |
| Spec 不能防止代码腐化 | 没有 spec，测试可能验证了错的东西 |

## 影响
- 每个 task 同时维护：spec.md + plan.md + tests/T-XXX/
- spec 的验收标准变更 → 必须同步更新测试
- 测试失败 → 先检查是 spec 错还是实现错
