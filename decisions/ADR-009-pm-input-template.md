# ADR-009 — 产品输入标准化（3+1 模板）

- **状态**：Accepted
- **日期**：2026-05-19
- **决策人**：大Joe + 婷婷 + 子健
- **会议来源**：2026-05-18 Harness Engineering 内部对齐会

---

## 背景

会议上产品（婷婷）和 GTM（子健）跟开发（百村 / 乐琴 / 阿和）就"PRD 写到什么程度"产生讨论：

- 太详细 → AI 上下文爆炸 + 偏差
- 太简略 → 开发猜，子健提出"避免另一个极端"
- 设计现在是 word，没框架

---

## 决策

产品输入**统一为 3 项核心 + 1 项规范**：

### 必填 3 项

| 项 | 内容 |
|---|---|
| ① 核心用户故事 + 主流程 | 像亚马逊新闻稿那样写用户旅程 |
| ② 业务边界 | 什么**不能**做（例：积分不能为负） |
| ③ 验收标准 | 产品如何验收（量化或可观察） |

### 必备 1 项

| 项 | 内容 |
|---|---|
| ④ 设计规范 | 不再用 word，抽象成总框架（设计 token / 组件清单 / 交互范式） |

---

## 两类项目分开处理

### 新项目
- 必须给一个 **demo-grade HTML 原型**（业务体验完全对，UI 丑没关系）
- 大Joe 原话：「丑点没关系，但业务体验完全是对的」
- 然后倒逼设计师做漂亮版

### 存量项目
- 用 **PRD + 增量描述**（V1.1 / V1.2 叠加）
- AI 读 current 版本
- 历史版本归档到 git，AI 不读

---

## 模板路径

- `templates/pm-input-template.md` — 3+1 模板
- 产品文档落地到项目内 `product/PRD-YYYY-MM-DD-<title>.md`

---

## 不可逾越的边界

- ❌ 产品**不写**接口定义
- ❌ 产品**不写**技术选型
- ✅ 产品**必须有**所见即所得的呈现（新项目）或清晰增量描述（存量项目）

---

## 解决的问题

| 痛点 | 决策如何解决 |
|---|---|
| AI 上下文爆炸 | PRD 控制在核心 3 项 |
| 婷婷&子健需求频繁变 | 增量叠加 + 标 current 版本 |
| 开发猜需求 | demo 原型 / HTML 让交互无歧义 |
| 设计不规范 | 抽象总框架而非每次出 word |
