## 2. 为什么改
解决多角色（产品/前端/后端/交互/运维/测试/设计）vibe coding 的两个真空：
1. v1.4 一次性硬拷贝接入，主仓库升级无法分发到下游项目
2. 没有跨角色契约层（API/事件/数据模型）和产品上下文层，AI 容易"想象接口"和"业务跑偏"

## 3. 思路
- 按"变化频率 + 协同方式"把 harness 拆两层：
  - 慢变（铁律/流程/ADR）→ `.harness/`，主仓库 PR + GitHub Action 自动分发
  - 快变（current/code-map/contracts/product）→ 项目自管理，code-map 在 merge 后自动刷新
- 大Joe 明确不要 hook、不要脚本约束开发中的行为 → 自动化只在 main 分支 push 后触发，不影响开发流程
- code-map 用 HUMAN/AUTO 双段设计，机器维护结构、人工标注语义

避坑（待写入 lessons.md）：
- 一次性 cp 接入是死局，必须分层 + 自动同步
- 不能用 hook 强制开发中行为，但 merge 后基础设施可以自动化
