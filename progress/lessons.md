# 踩坑日志 — futurx-coding-harness

> 凡是"业界推荐但其实错的"方案，记录在此。AI 读完后**禁止再用**。

## L-001 — 不要把 superpower skill 内容嵌入 AGENTS.md

- **场景**：v1.4 决定集成 superpower 工具箱
- **错误方案**：把 12 个 superpower skill 的内容**复制粘贴**进 AGENTS.md
- **为什么 AI 会默认推荐**：直觉上"一个文件搞定所有规范"看起来很合理
- **真实问题**：
  1. AGENTS.md 会膨胀到几千行，违反轻量化共识
  2. superpower 升级时本仓库无法同步
  3. 强制每个用户都接受 superpower 的所有约束，违反"自愿"原则
- **正确方案**：AGENTS.md 只**列名字 + 一句话**，让 agent 按需调用独立的 skill 文件
- **加入**：2026-05-19 by 大Joe + 阿和（会议共识）

## L-002 — 不要把"强制"和"推荐"混在一起

- **场景**：v1.3 之前 AGENTS.md 有 10 条 RULES，每条都是"硬约束"
- **错误方案**：所有规则平铺，全部用"必须"语气
- **真实问题**：agent 和团队成员无法区分哪些是真红线，哪些是建议，导致全部当成强制 → 团队抵触
- **正确方案**：明确分级 → 铁律（4 条） / 强烈推荐 / 推荐 / 随意
- **加入**：2026-05-19 by 阿和（"我们只需要把框架弄好就行"）

## L-003 — 不要强制全员用同一个 IDE 或 spec 工具

- **场景**：v1.0 时考虑过强制 spec-kit
- **错误方案**：要求所有人按 spec-kit 13 步走
- **为什么直觉上合理**：流程统一似乎能减少协作摩擦
- **真实问题**：百村等老炮已有自己的工作流，强制会大幅降低效率；spec-kit 在 tricky 项目里会污染 AI 上下文
- **正确方案**：只对齐 commit 上来的代码质量和 progress 记录，个人 spec / 工具自由
- **加入**：2026-05-19 by 百村 + 阿和（会议共识）
